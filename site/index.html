The interface

Five pages on one window. These captures come from a 13th-gen Intel i5 laptop with 16 GB of RAM, on Wayland/Hyprland, not a GNOME session.

Built around one question

Can this machine run this model, and how fast? Every feature feeds that answer without guessing.

  • Hardware discovery

    CPU and RAM, NVIDIA VRAM through NVML, AMD VRAM and GTT through sysfs. Missing readings stay unknown, never zero.

  • Conditional memory fit

    Weights, K/V cache, compute buffers and runtime allowance for an explicit context, with a per-component breakdown.

  • Model catalog

    Hugging Face GGUF search with pinned revisions, deduplication, resumable downloads and a keyring token.

  • Attached runtimes

    Discover Ollama, LM Studio and vLLM on loopback. Kvlm never stops them, edits their units, or deletes their models.

  • Managed llama.cpp

    A checksum-verified portable install, launch profiles, and supervised start, stop and restart on 127.0.0.1.

  • Speed test

    One explicit, cancellable streaming request to a local Ollama model, with decode rate and sampled RAM, VRAM and GTT peaks.

  • Experiments

    Cold and warm runs on the managed llama.cpp server, diagnostics with evidence, A/B comparison, and a one-setting follow-up.

  • Developer exports

    Continue.dev, Zed and OpenCode snippets plus a systemd --user unit, generated as text you copy. No account and no cloud step.

From a file to a verdict

Fit estimates are conditional, not promises. A saved benchmark proves one prior request, not every future context or placement.

The arithmetic

For a supported GGUF layout, Kvlm adds the resident weights, the K/V cache at your context length, compute buffers, and a runtime allowance. The calculator never probes or downloads anything by itself.

  • Weights
  • K/V cache
  • Buffers
  • Runtime

When metadata is missing, the answer is Unknown, not an optimistic fit. Layout warnings block the breakdown path.

Verdicts

  • Comfortable. Fits the stated context with room to spare.
  • Constrained. Fits, but leaves little headroom.
  • Not recommended. Exceeds the supplied pools.
  • Unknown. Not enough data to answer.

Verdicts always carry a text label, never colour alone.

It does not touch what it does not own

Attached: yours, read-only

Ollama, LM Studio and vLLM are discovered on loopback. Kvlm lists their models and reads memory and loaded state. It never stops or restarts them, edits their system units, or deletes their files.

Managed: installed and owned

Kvlm can install a portable llama.cpp build it verifies, start and stop it on 127.0.0.1, read bounded logs, and benchmark it on the Experiments page.

Install

Kvlm is a beta built from source. You need Linux, Rust stable 1.92+, GTK 4.12+, Libadwaita 1.4+, Meson, Ninja, a C toolchain and pkg-config.

Terminal~/.local
git clone https://github.com/dexterhere/kvlm.git
cd kvlm
scripts/install.sh

The installer checks dependencies, prints the package command for your distribution if something is missing, and installs under ~/.local. It never runs sudo. Use --check to report only, or --uninstall to remove it.

Release files

Version tags attach kvlm-<version>.flatpak, kvlm-<version>-x86_64.AppImage and SHA256SUMS to the GitHub release.

Both are built in CI. Neither has been installed and run on a real machine yet. If they do not work, build from source. There is no store package.

Reporting a hardware problem

Run local-ai-workstation --report-hardware and attach the output. Device identifiers, paths and times are removed.

Privacy is the default

Kvlm is a local control plane. It does not need an account, a backend, or a background connection.

  • No telemetry and no crash uploads.
  • Startup makes no network request at all.
  • The network is touched only after you press a button.
  • A Hugging Face token lives only in the desktop keyring.
  • Benchmark history stays in a local SQLite database.
  • Attached runtimes are read-only and no root is required.
